# 需求规格

## 目标

在现有两个自动更新归档之上，部署可以实际使用的统一文档资源库，连接 Windows Obsidian，并保留未来研报应用对接能力。

| 编号 | 需求 |
|---|---|
| R01 | 两个原目录只读，不搬家、不重命名、不复制全量附件、不改变下载流程。 |
| R02 | 本机只读读取财报 SQLite（遵循 WAL，不用 immutable）；读取 Discord JSONL。统一来源、标题、日期、ID、版本、路径、哈希等元数据。 |
| R03 | 新增、元数据编辑、内容换版都可增量更新。稳定文件名避免改标题导致重复卡片；重复执行不产生内容抖动。异常读取不得造成删库或重置目录。 |
| R04 | 报告期、披露日期、推送时间不同字段；未知值保留未知；修订和历史版本可追溯。 |
| R05 | 自动生成 Obsidian Markdown 卡片、首页、资料视图；已有标题/消息摘要提供可搜索入口，不虚构全文分析。 |
| R06 | 原文通过固定文档/版本 HTTP 地址按需读取，支持 PDF 的 Range/HEAD、正确 MIME、中文标题与无扩展名文件。ID 查找禁止任意路径访问。 |
| R07 | HTML 原文隔离提供，避免与应用同源执行不可信脚本；不承诺外链资源已离线化。 |
| R08 | 元数据查询 API 支持来源、公司、日期、关键字、分页；返回稳定 ID、原文访问地址；明确第一版不是 PDF 全文或语义搜索。 |
| R09 | server vault 与客户端指定 Vault（用户配置的本地路径）双向同步，仅笔记/卡片/小附件，不包含原始归档、catalog、state、凭据。 |
| R10 | 服务自动重启，按小时对账，Windows 同步后台隐藏启动并开机/登录持久化；安装可重复，保留已有配置。 |
| R11 | 人工研究区与生成区分离，自动程序不覆盖人工笔记。同步冲突保留与版本恢复可追踪。 |
| R12 | 每个开发项必须对应需求、设计、测试与部署记录；问题记录有时间、现象、原因、处理与状态。 |
| R13 | 所有必要软件可自主安装；仅真正必须用户交互时提出。服务仅 LAN/VPN，管理面不公开，不修改已有网络设置。 |
| R14 | 数据可迁移：标准 Markdown + 独立索引/清单 + 稳定引用。记录备份/恢复方式，不能把双向同步宣传成备份。 |
| R15 | 中文状态面板：根路径以清晰中文区分“原始归档→目录/卡片→Windows Vault”，展示入库/同步最近与下次检查、来源与文档计数、变更与异常；明确空/加载/错误/离线/过期状态与 Asia/Shanghai 时间；只读刷新，不触发入库，不新增可写端点；无外部资源，元数据检索仍明确非全文。 |
| R16 | 变更与同步观测须诚实可持久化：变更账本仅记语义变化且无变化为零，升级播种基线不误报历史导入；调度状态可判定运行/过期/停止/无历史；同步面板经只读窄采集器读取本任务 Syncthing，绝不暴露凭据/完整设备 ID/私有路径，未知值保持未知，服务器本地空闲不等于 Windows 已同步。 |

## 本次不做

不做报告下载、不全量 OCR 或大模型分析、不构建交易信号/下单、不购买 SaaS、不把全文交给第三方云、不部署 RAGFlow。手机端同步后续单独选择，本次验收设备为 Windows + Linux。
